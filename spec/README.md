# spec/ — Fuente de verdad del proyecto

Si el código y `spec/` no coinciden, manda `spec/`. Primero se corrige aquí y después en el código.

| Documento | Responde a |
|---|---|
| `dominio.md` | ¿Qué cosas existen y cómo se relacionan? |
| `alcance-y-planes.md` | ¿Qué entra, qué no, y qué incluye cada plan? |
| `nfr.md` | ¿Qué tan rápido, seguro y disponible debe ser? |
| `casos-de-uso/` | ¿Qué hace cada perfil, paso a paso? (por escribir) |
| `bdd/` | ¿Cómo sabemos que funciona? Escenarios en Gherkin |
| `contratos/` | ¿Qué rutas hay, qué reciben y qué devuelven? |
| `adr/` | ¿Qué se decidió y por qué? |
| `seguridad/` | Amenazas, controles (ISO/IEC 27001) y pagos (PCI DSS) |
| `gobierno/` | Objetivos, responsables, riesgos, proveedores, cumplimiento (COBIT 2019) |
| `privacidad/` | Datos personales (Ley 21.719, ISO/IEC 27701) |
| `servicio/` | Operación: niveles, cambios, incidentes, respaldo (ITIL) |
| `mejora-continua/` | Indicadores, registro de mejoras, revisiones |

Estados usados en los documentos: **Propuesta** (falta aprobar), **Aceptada**, **Pendiente**
(falta escribir o hacer), **Ilustrativo** (valor de ejemplo sin fuente verificada).
